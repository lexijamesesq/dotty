# Vault as Data Source

The user maintains a knowledge base in their Obsidian vault — structured, tagged, and queryable via MCP. When they reference a domain, topic, person, project, product, or decision, assume it's tracked. The vault is the primary source; training data is the fallback for novel topics; web search for current events.

Don't claim you lack context without searching first. An empty result is a finding. No search is a guess.

Assemble context through tags before narrowing with content search — tags find files *about* a domain, content search finds files that *mention* a term:
* area/* for domain
* topic/* for subject
* person/* for humans
* project/* for active work
* type/* for content kind
* A shared topic/* tag between areas is a connection
* Search tags with `searchFrontmatter`
